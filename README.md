# FDE 前沿部署工程师 Skill

一个给 AI Agent 用的 **FDE（Forward Deployed Engineer）工作手册**。
装上它，你的 Agent 就会以「派驻客户现场的前沿部署工程师」身份工作——不把模型讲清楚，而是**把 AI 嵌进客户的业务流程，让它真的被用起来，并且算得出账**。

---

## 这是什么

不是一份资料合集，是一个**可执行的交付流程**：

- **六条铁律**：先对齐再动手 / 一切结论带数字 / 不确定就标 `[需确认]` 绝不编 / 公开 benchmark 高 ≠ 你的场景好 / 复杂度是成本 / 合规红线不可协商
- **九步工作流**：客户画像 → 需求拆解 → 方案生成 → 技术选型 → 落地实施 → POC 验收 → 交付上线 → ROI 度量 → 推广扩量，每步都有交付物和完成标准
- **13 份现场手册**：按需加载，不到 300 KB，覆盖选型、推理优化、分布式、成本、本体建模、合规、采纳运营
- **8 个交付物模板 + 1 组填好的样例**：客户画像卡、需求文档、技术方案、POC 方案、验收报告、ROI 报告

**核心立场：「交付」不等于「落地」。** 交付＝东西上线了；落地＝业务方在真实流程里天天用它、不用反而别扭。按「落地」验收，不按「交付」验收——上线了但没人用，等于没做。

---

## 给谁用

- 做 **AI 落地 / 私有化部署 / 行业解决方案**的工程师和产品经理
- 需要在客户现场做**需求拆解、模型选型、POC、验收**的人
- 想把「AI 项目为什么做不成」这件事**量化**的人

**不适合**：想学模型原理 / 刷论文 / 只做纯算法研究的人。这里不讲 Transformer，讲的是怎么让项目上线后被真的用起来。

## 怎么装

把整个 `fde/` 目录放到对应工具的 skills 目录下（目录名保持 `fde`）：

| 工具 | 安装位置 |
|---|---|
| **WorkBuddy** | `~/.workbuddy/skills/fde/` |
| **Claude Code** | `~/.claude/skills/fde/`（项目级则放 `<项目>/.claude/skills/fde/`） |
| **Codex** | `~/.codex/skills/fde/` |

```bash
git clone <this-repo> fde
mkdir -p ~/.workbuddy/skills && cp -R fde ~/.workbuddy/skills/
```

装完**新开一个会话**才对生效（技能的清单在会话开始时加载一次）。

## 怎么触发

正常提问即可，Agent 会按描述自动加载。例如：

- 「客户想用 AI 做设备故障预测，我该怎么拆需求？」
- 「70B 模型私有化部署，要几张卡？怎么估成本？」
- 「客户业务数据很乱，表结构没人看得懂，从哪下手？」
- 「帮我把这个 AI 项目的验收标准写成可量化的。」

**如果没有自动加载**，在提问开头直接写一句：

> 用 fde skill：客户想用 AI 做设备故障预测，我该怎么拆需求？

## 未覆盖范围

说清楚边界，免得你找半天：

- **不含具体厂商的报价与合同条款**——那些随地区、时间变化，必须现场询价。手册里凡是价格类数字都标了 `[需确认]`。
- **不含某个具体行业的完整案例**——本仓库的案例是通用推理部署与本体建模场景。
- **不涉及模型训练与微调**——聚焦「不训模型，把模型接进业务」，这覆盖了企业 AI 落地约 80% 的需求。
- **不含等保 / 备案的实操流程**——合规手册覆盖 PIPL、数据安全法分级、行业监管，但等级保护与算法备案的具体申报流程未收录。
- **国内薪酬与职业数据为公开市场调研口径**，非实时更新。
